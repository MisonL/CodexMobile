## Findings

### P1: Relay streaming chunk 异常路径未清理 pending request

- Evidence: `server/relay-runtime-stream-response.js:27` 到 `server/relay-runtime-stream-response.js:35` 在 `streamStarted` 缺失或 `sequence/bytes` 校验失败时直接 `throw`，未调用 `pendingRequests.settle`。
- Impact: 上层 `server/relay-runtime.js:236` 到 `server/relay-runtime.js:241` 会捕获错误并调用 `failMacRequest`，但同一个 pending request 仍可能留在 pending map 中直到超时，导致 pending 计数、timer 和 onChanged 状态延迟清理。该问题影响 relay streaming 错误路径，不改变本轮 CLI 命令验证结果。
- Action: 已在 `tasks.md` 追加 `CM-CLI-007`，状态为“未开始”，用于独立修复和补负向测试。

### P2: CLI 退出码仍使用裸数字

- Evidence: `cli/commands.mjs:67` 的 `errorResult(message, code = 2)`，以及多个 `code: 0` / `code: output.ok ? 0 : 1`。
- Impact: 行为正确，测试覆盖充分，但与 `AGENTS.md` 的 magic number 约束不完全一致。该问题不属于严重功能或安全问题，本轮不修改业务代码，也不阻塞 CM-CLI-006 收口。
- Action: 记录为后续质量债；若继续严格执行 magic number=0，应在单独任务中抽取 `EXIT_CODE_SUCCESS`、`EXIT_CODE_FAILURE`、`EXIT_CODE_INVALID_USAGE`。

### P2: CodeRabbit 对非 CLI/既有 relay 文件报告大量复杂度和 magic number 债

- Evidence: CodeRabbit 对 `scripts/relay-mac-client-http.mjs`、`scripts/relay-mac-client-realtime.mjs`、`scripts/relay-mac-client-local.mjs`、`server/realtime-voice-handoff.js`、`server/http-utils.js` 等返回 refactor 或 minor potential issue。
- Impact: 这些问题大多超出 CM-CLI-006 的 CLI 阶段审计边界，且当前 `npm run smoke:relay` 通过。除 P1 已追加任务外，其余不在本审计任务中展开修改。
- Action: 作为范围外质量信号记录，不追加修复任务。
