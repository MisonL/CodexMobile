# CR-CM-CLI-009 - Review 收尾优化

## 范围

修复 `codex/relay-phase1` 相对 `main` review 后续确认的 CLI 问题：

- `codexmobile start` 对 stale PID 复用误判为已运行。
- macOS LaunchAgent `install` / `enable` 重复执行时可能因服务已加载而失败。
- malformed managed state 在 PID 存活时不应被当成已运行服务。
- LaunchAgent `bootout` 只能忽略服务未加载或不存在类错误，不能吞掉真实 `launchctl` 失败。
- `install --dry-run` 输出需要标明 `bootout` 仅允许未加载或不存在类错误失败。

## 修复

- `cli/process-manager.mjs`：`startManagedServer` 在已有 managed PID 且进程存在时，复用 `stop` 的命令行归属校验；若 PID 已被其他进程复用或 state 结构不完整，清理 stale state 并重新 spawn。
- `cli/launch-agent.mjs`：`installMacLaunchAgent` 和 `enableMacLaunchAgent` 在 bootstrap 前先尝试 `bootout` 当前用户服务；仅对服务未加载或不存在类 `bootout` 错误保持幂等，其他 `launchctl` 错误继续抛出；对已加载类 bootstrap 错误保持幂等，随后继续 `kickstart`。
- `cli/launch-agent.mjs`：`install --dry-run` 计划增加 `notes`，明确 `bootout` 仅忽略未加载或不存在类错误，避免把真实行为表示成所有错误都会被忽略的 shell 命令。
- `cli/launchctl-policy.mjs`、`tests/cli-launchctl-policy.test.mjs`、`tests/cli-process-manager-start.test.mjs`：拆分 LaunchAgent 错误策略 helper，覆盖真实重复 bootstrap 错误文本和 missing bootout target，并保持相关文件不超过 300 行。
- `README.md`：同步 CLI 行为说明和 Windows 命令行归属校验限制。

## 审查结论

- 在支持命令行归属校验的平台上，`start` 不再只凭 PID 存活跳过启动。
- `stop` 仍只停止命令行匹配的 CodexMobile managed process。
- LaunchAgent 重复安装和启用的调用顺序稳定：`bootout`、`bootstrap`、`kickstart`。
- macOS 和 Linux 可通过 `ps` 校验 PID 命令行归属；Windows 当前只做 PID 存活判断，未覆盖命令行归属校验。
