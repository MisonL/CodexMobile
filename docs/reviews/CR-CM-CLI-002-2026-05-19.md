## Review Notes

- `stop` 只会停止状态文件中 `kind=codexmobile-server` 且命令包含 `serve` 的 CLI 管理进程。
- 已有管理进程仍在运行时，`start` 不会重复 spawn 第二个服务。
- 状态文件残留但 PID 不存在时，`stop` 只清理状态，不调用 kill。
- `logs` 会脱敏 `CODEXMOBILE_RELAY_SECRET=...`、`CODEXMOBILE_PAIRING_CODE=...`、`Pairing code: ...`、`Authorization: Bearer ...` 和 URL 中的 `token=...`。
- Windows 子进程环境保留 PATH 去重逻辑，避免 PATH/Path 重复导致启动异常。
